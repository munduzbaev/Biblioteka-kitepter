# website — сайт библиотеки

Публичный сайт на чистом HTML, CSS и JavaScript (без сборки и фреймворков). Показывает каталог с поиском и сортировкой, читалку-«листалку» для PDF и страницу входа. Данные берёт из API (`../APIs`), вход — через Supabase Auth. Деплоится на Vercel как статический сайт.

```
website/
├── index.html           # каталог: поиск, фильтры, сортировка, окно книги
├── read.html            # читалка (листалка PDF)
├── login.html           # вход, регистрация, сброс пароля
├── css/                 # style.css (каталог, вход), reader.css (читалка)
├── js/
│   ├── config.js        # адреса API и Supabase  <-- здесь настройки
│   ├── app.js           # каталог
│   ├── auth.js          # вход через Supabase Auth (сессия в localStorage)
│   ├── login.js         # страница входа
│   └── reader.js        # читалка
├── vendor/              # PDF.js и StPageFlip (с лицензиями), без внешних CDN
├── tests/               # браузерные тесты (Playwright), на Vercel не нужны
└── vercel.json
```

## Настройка: `js/config.js`

| Значение | Что вписать |
|---|---|
| `API_URL` | адрес задеплоенного API (`https://….vercel.app`); на `localhost` автоматически `http://localhost:8000` |
| `SUPABASE_URL` | адрес проекта Supabase: `https://<ref>.supabase.co` |
| `SUPABASE_ANON_KEY` | **публичный** ключ `anon` / `publishable` (Supabase → Project Settings → API) |

Ключ `anon` публичный по замыслу: он попадает в браузер любого посетителя, его можно хранить в Git. А вот **секретные** ключи (`service_role`, пароль к базе) сюда вставлять нельзя — они есть только у API и админки.

## Запуск локально

Сайту нужен любой статический сервер:

```bash
python -m http.server 5500       # http://localhost:5500
```

Для работы нужен запущенный API (`../APIs`, порт 8000) и заполненный `SUPABASE_ANON_KEY`.

## Что умеет

**Каталог.** Поиск по названию, автору и описанию (без учёта регистра), фильтры по жанру и языку, сортировка по названию, автору, году, рейтингу и объёму, пагинация. Состояние хранится в адресе (`?genre=…&sort=…&page=2`), поэтому ссылкой можно поделиться. Светлая и тёмная тема. Архивные книги на сайте не видны.

**Вход.** Читать книги и покупать файлы могут только вошедшие читатели. Регистрация, вход и «Забыли пароль?» идут через Supabase Auth, пароли хранит Supabase. После входа читателя возвращает туда, откуда он пришёл (адрес возврата проверяется: только внутри сайта). Токен обновляется автоматически.

**Читалка** (`read.html?id=ID`, по образцу narynlib.kg). Листание с анимацией (клик, свайп, кнопки, стрелки ←/→), на компьютере разворот, на телефоне одна страница; переход по номеру; зум 100–300% (`+`/`−`); полный экран (`F`, в нём колесо мыши листает); поиск по тексту (только если в PDF есть текстовый слой, у сканов нет); звук листания (включается кнопкой). Страницы рисуются лениво, большие книги не тормозят. Адрес `?page=N` открывает нужную страницу. Кнопок «скачать», «печать», «поделиться» нет.

> Это защита от случайного копирования, а не абсолютная: браузеру для показа нужен сам PDF, поэтому технически его можно сохранить. То же верно для любой онлайн-читалки.

**Покупка.** У каждой книги своя цена (её задаёт админка). Кнопка «Купить файл» пока отвечает «Покупка пока недоступна»: оплата через Mbank ещё не подключена.

## Тесты

Браузерные тесты на Playwright. Сайт отдаётся встроенным статическим сервером, а API и Supabase заменены имитацией: настоящие база, аккаунты и файлы не затрагиваются.

```bash
cd tests
npm install
npm run install-browser     # один раз: скачивает Chromium для Playwright
npm test
```

Покрыто: каталог (поиск, фильтры, сортировка, пагинация, адрес, окно книги, ошибки), читалка (листание, переход, зум, поиск, телефон, ошибки), вход (ошибки, регистрация, выход, обновление токена, защита чтения и покупки, безопасность адреса возврата).

## Деплой (GitHub → Vercel)

1. Впишите адреса и `SUPABASE_ANON_KEY` в `js/config.js`, отправьте в GitHub.
2. Vercel → Add New → Project → репозиторий `Biblioteka-kitepter`, Framework: Other, без build-команды. Root Directory оставьте пустым: сайт лежит в корне репозитория.
3. Дальше каждый `git push` в `main` обновляет сайт автоматически.

В Supabase → Authentication → URL Configuration добавьте адрес сайта (Site URL), чтобы ссылки из писем о подтверждении почты и сбросе пароля вели на него.
